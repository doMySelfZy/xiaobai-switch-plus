# 性能优化：消除卡顿，让交互达到极致流畅

## Goal

用户明确提出的体验目标：**极致流畅**。一次性能专项评审（5 个并行代理 + 人工核实）在现有代码里
定位到一批可复现的卡顿来源，覆盖拖动、输入、后台轮询、网络等待、渲染合成与后端阻塞六个方面。
这些问题不是本次拉取引入的，是应用既有的形态；本任务统一修复。

评审结论里已人工核实的三条（其余来自代理的逐行定位，实施时逐条对照代码再确认——
按 `.trellis/spec/guides/index.md` 的提示，AI 复核结论约 35% 为误报，必须落到代码上验证）：

- 悬浮窗每次 `mousemove` 发一次 IPC（`FloatingWindow.tsx:306`），且位置算法是反馈环；
- 站点配额定时器只判窗口可见性、不判当前页面（`SitesPage.tsx:105-108`）；
- `useSiteDeepLink` 每 400ms 轮询一个在 Windows 上永远不会被写入的文件。

## Requirements

**必须遵守（AGENTS.md 为唯一权威源）：**

- 不改任何产品行为、协议值、数据格式与兼容红线：`xiaobai_` 命名空间、WebDAV manifest 名与
  远端目录默认值、备份前缀与包内条目名、更新签名公钥、深链 scheme、`restore_official` 与
  孤儿清理识别逻辑。
- 不破坏同步引擎的既有不变量（见 `.trellis/spec/backend/webdav-sync.md`）；`FINGERPRINT_TABLES`
  与 `FINGERPRINT_ALGORITHM_VERSION` 的关系不得破坏。
- i18n：所有新增用户可见文案走 `react-i18next`（`zh-CN` + `en-US`），插值用双花括号。
- 组件内 message/modal 从 `App.useApp()` 取，禁止 antd 静态调用。
- 副作用必须可清理；effect 依赖里的函数用 `useCallback`；纯函数放组件外。
- 不引入新的状态管理库或动画库；不新增运行时依赖（Rust 侧如确有必要，需在 design.md 说明理由）。

**约束：**

- 每条改动都要能指出"改前为什么慢"，不接受需要真机剖析才能定性的微优化。
- 保持既有正确的做法不被顺手改坏（见 design.md 的"已确认良好、不要动"清单）。

## Acceptance Criteria

### 批次 A：交互手感
- [ ] A1 悬浮窗拖动改为系统拖动，`setPosition` 从 mousemove 路径移除；拖动跟手、可越过窗口边界不冻结；点击穿透判定保留（拖完不误触发收起）
- [ ] A2 主窗口标题栏拖动无 200ms 死区；双击最大化/还原行为保留
- [ ] A3 悬浮窗 `getCurrentWindow()` 引用稳定，拖动/折叠相关 listener 不再每次渲染重挂
- [ ] A4 模态遮罩与悬浮窗玻璃层去掉 backdrop-filter，且目视确认视觉无回退
- [ ] A5 `GoApplyButton` 在站点页不可见时不跑定时器
- [ ] A6 模型搜索输入不被 chip 重渲染阻塞（deferred 过滤）

### 批次 B：后台工作与轮询
- [ ] B1 非站点页时配额定时器与 focus 探测不发请求；后台刷新不绕过 TTL（手动刷新仍 force）
- [ ] B2 深链轮询仅在需要它的平台启用（Windows 上零轮询），运行时深链仍可用
- [ ] B3 模型测试结果按帧批量提交，不再每行一次全列表重渲染
- [ ] B4 Proxy/MCP/Skills/Rules 页细粒度订阅 + columns memo，输入框不再重渲染整页

### 批次 C：输入与设置
- [ ] C1 设置页数字输入本地草稿 + 失焦/防抖提交，不每击键写库，clamp 不回填打断输入
- [ ] C2 `save_settings` 不再每次都全量扫描备份目录

### 批次 D：网络等待与进度
- [ ] D1 站点协议检测并行尝试 + 总超时预算，最坏等待 75s → ≤15s，有进度与取消
- [ ] D2 模型列表拉取同样处理；刷新期间保留旧列表不清空
- [ ] D3 agent/MCP 版本检查：子进程加超时、并行、避免每次进页面都跑
- [ ] D4 技能安装候选源不再串行各等 45s
- [ ] D5 站点启用开关不再因强制探测显得"点了没反应"

### 批次 E：后端阻塞与锁
- [ ] E1 写配置类命令不再在 UI 线程执行 fsync/备份/剪枝
- [ ] E2 同步快照的 hash/压缩移出全局 DB 锁
- [ ] E3 WebDAV 超时分层；只读列表不抢占同步操作锁；保存配置不等待同步

### 全局验证
- [ ] `cargo test` 全绿（基线 540 passed / 0 failed / 2 ignored）
- [ ] `pnpm test:run` 无新增失败（基线 374 passed，2 个文件为既有收集期 SyntaxError）
- [ ] `pnpm typecheck` 通过
- [ ] 构建 NSIS 包并安装到本机，人工确认拖动、输入、切页手感

## Notes

- 风险最高的是批次 E（触碰同步与文件写入路径）。若风险不可控，允许只做 E1/E3 的低风险部分、
  把 E2 记入后续任务，但必须在 implement.md 写明未做原因，不得默默缩小范围。
- 每条改动独立提交，便于单条回退。
