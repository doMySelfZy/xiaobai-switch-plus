# 站点表单重排 + 请求头全局化 + 代理页与 MCP 更新修复

## Goal

按产品负责人对 7 项设计的质疑、以及随后的代码评审结论，做一轮"配置精简 + 交互纠错"改造：

1. 站点表单：连接协议改为自动检测（可手动覆盖），备注移回基本信息区，NewAPI 令牌 / 用户 ID 归位，修正错误文案，统一这一块的布局。
2. 请求头：从"每站点配置"改为"代理级全局默认 + 站点可选覆盖"。
3. 本地代理页：去掉重复控件与矛盾文案，并修复一个会写坏用户 CLI 配置的真 bug。
4. MCP「检查更新」：让它真的能用，且不再污染跨设备同步状态。
5. 三个既有缺陷：`detect_protocol` 重复请求、WebDAV 手动备份可能挤掉同步指针、`sync.rs` 与实现矛盾的注释。

## Background

产品负责人逐条质疑了站点高级配置、请求头位置、备份与同步机制、技能中心 Agents 分类、ZCode 目标、MCP 检查更新、本地代理交互与日志生命周期共 7 项。调研结论（含证据）见 `Notes`。其中三项的前提与代码事实相反（Agents 分类有真实用途、ZCode 早已支持桌面端、连接协议删不掉只能自动化），已在进入本任务前与负责人确认。本任务只承载**已确认**的改造。

## Requirements

### R1 站点表单重排与协议自动化

- R1.1 连接协议默认自动：用户不需要选择协议，保存 / 测试连接时自动探测并落库；下拉降级为覆盖入口，并明确标注"自动检测结果，可手动覆盖"。
- R1.2 备注移出「高级配置」，回到基本信息区；且"备注非空就自动展开高级配置"的行为随之取消。
- R1.3 NewAPI 访问令牌与用户 ID 移出站点连接配置，归到与额度相关的位置。
- R1.4 修正 `protocolHint` 的错误文案（当前写"不确定时可留空…自动检测"，而该下拉并没有空态）。
- R1.5 「高级配置」重新分组，与站点表单其它区域的视觉语言一致。

### R2 请求头改为代理级全局默认 + 站点覆盖

- R2.1 本地代理页新增「默认请求头」，加密存储。
- R2.2 站点级请求头保留，但降级为「本站覆盖（可选）」，界面上与全局形成"继承 / 覆盖"的区分。
- R2.3 转发时合并顺序固定为：全局 → 站点覆盖，同名以站点为准。
- R2.4 全局请求头**必须跨设备同步**：数据放新表 `local_proxy_headers` 并加入 `FINGERPRINT_TABLES`，同时把 `FINGERPRINT_ALGORITHM_VERSION` 1 → 2（清单变化会改变指纹）。代价是对端未升级前同步会显式暂停并提示"请先升级对端"——必须写进发版说明。

### R3 本地代理页精简与端口 bug 修复

- R3.1 启停控件只保留一个（当前标题栏按钮与卡片开关完全重复）。
- R3.2 「刷新」按钮与 4 秒自动轮询职责重叠，合并或降级。
- R3.3 `portHint` 文案与实际行为一致（现在写"需要重启才会生效"，实际会自动重启）。
- R3.4 修复改端口导致的"磁盘已接管 / DB 与 UI 未接管"错位，以及由此引起的：退出应用时不写回直连、CLI 永久指向一个没人监听的端口。
- R3.5 "停止代理会关闭全部接管"必须在界面上说明；重新启动代理能恢复用户之前的接管选择。

### R4 MCP 检查更新可用化

- R4.1 包名解析支持 `command: "npx"` + 包名在 `args` 的形态（含 uvx）。
- R4.2 无法解析的条目在界面上如实显示"不支持检查更新"，不再静默无输出。
- R4.3 版本检查结果不再写入参与同步指纹的表（不得通过改指纹计算实现，见 R2.4 同款约束）。
- R4.4 对可解析条目，单条更新与一键更新保持可用。

### R5 三个既有缺陷

- R5.1 `detect_protocol` 不再对同一（鉴权方式 + 伪装）组合重复发请求。
- R5.2 WebDAV 远端剪枝不得删除 manifest 当前引用的那个备份包。
- R5.3 `sync.rs` 中与实现、规格文档相矛盾的字段注释纠正。

## Constraints（兼容红线）

- **不删列**：`sites` 表上的 `zcode_api_type`、`notes`、`proxy_headers_*` 等一律保留。同步指纹按列哈希，删列会让新旧版本对同一份业务数据算出不同指纹，正是历史上"两端互相覆盖"事故的成因。
- **指纹算法版本必须随清单变化递增**：`compute_logical_fingerprint` 对每张表 `SELECT *` 后**逐列哈希**（`sync.rs:81-86`），所以「给已入清单的表加列」与「往清单里加表」同样改变指纹。本任务把 `local_proxy_headers` 加入 `FINGERPRINT_TABLES`（9 → 10），因此**必须**把 `FINGERPRINT_ALGORITHM_VERSION` 1 → 2、并更新 `sync.rs:711-729` 的护栏测试（该测试会拦住忘记递增的改动，不要绕过）；`LEGACY_FINGERPRINT_ALGORITHM_VERSION` 保持 1。
- **`mcp_update_state` 严禁入清单**：它是设备本地状态，入清单会让"检查更新"这个动作弄脏指纹。
- **请求头继续加密**：写入与转发两层校验都要保留（WebDAV 会把别的机器的库整包搬过来，脏数据必须在这两层挡住）。
- **新增列必须挂进 `ensure_incremental_schema`**：`CREATE TABLE IF NOT EXISTS` 不会给已有表补列，漏掉任何一个"库已存在"分支都会让老库拿不到新列且不报错。
- **与进行中的 perf-smoothness 任务时序规避**：该任务（状态 in_progress）要改造 `models_fetch/mod.rs` 的 `detect_protocol` 超时与并行、以及 `sync.rs` 的锁范围，与本任务 R5.1 / R5.3 落在同一文件同一函数。这两项放到本任务最后做，动手前先确认对方已落地，避免同函数双改。

## Notes

调研依据（每条都有文件:行证据，完整结论见本轮会话）：

- **请求头只在走代理时生效**：唯一消费方是 `local_proxy/forward.rs`（`merge_headers` 仅被 `server.rs` 调用），直连路径完全不注入；站点级"纯迁移到全局"会丢失多站点各需不同头的能力（例如 OpenCode Go 要求的 UA 与会话头）。
- **备份与同步机制**：本地整库备份默认保留 30 份、云端每设备 3 份；每次上传现场重新打整库包；方向判定只比较三个指纹，**不比较设备 ID**、无合并、无冲突交互框，两边同时改时云端赢。
- **技能中心 Agents**：装到 `~/.agents/skills/`，是 Agent Skills 生态的跨客户端共享层（Codex CLI 当前的用户级技能目录即此），删除会丢失真实能力 —— 保留，仅改文案（不在本任务范围）。
- **ZCode**：官方只发布桌面端（Electron），其配置就是 `~/.zcode/{v2,cli}/`，本项目已支持桌面端；误解源自自带文案 `settings.zcodeHomeHint` —— 只改文案（不在本任务范围）。
- **MCP 检查更新失效的结构性原因**：App 的两条安装路径与扫描纳管产出的都是 `command: "npx"` + 包名在 `args`，而解析器只认"命令里内联包名"；仓库内另有一份被废弃但解析口径正确的实现可参考。
- **本地代理端口 bug**：`commands/proxy.rs` 改端口时先 stop（清空接管集合并写回直连）、再用 stop 之前抓取的旧接管列表把客户端写回代理地址，导致磁盘与 DB 状态不一致，且退出应用时遍历的是空集合、不做恢复。
- 本任务**不含**：性能 / 流畅度优化（由 `09-15-perf-smoothness` 任务承载）、技能中心 Agents 文案、ZCode 文案与真机验证。
