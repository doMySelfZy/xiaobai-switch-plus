## 体验问题

### 1. 信息层级混乱
**问题：**
- "高级配置" Collapse 内部又包含两个分组（站点信息、代理配置）
- 三层嵌套（主表单 > 高级配置 > 子分组），视觉层级不清晰
- "站点信息"分组名称与整个表单主题重复，语义不明确

**影响：**
- 用户不清楚哪些是"高级"配置，哪些是"基础"配置
- Divider 分隔线在 Collapse 内部看起来像是二级内容，降低了可感知性

### 2. 配置项归类不合理
**问题：**
- "连接协议"对功能影响很大，但藏在"高级配置"里
- "测试连接"是验证必填字段的关键操作，却不显眼
- "写入预览"功能对大多数用户来说不重要，但占据显著位置

**影响：**
- 新手用户可能遗漏关键设置（协议选择）
- 高频操作（测试连接）被折叠隐藏

### 3. Collapse 交互成本高
**问题：**
- 需要手动展开两个 Collapse 才能看到所有配置
- 编辑站点时，如果要修改代理或能力，需要重新展开
- 没有"记住展开状态"的机制

**影响：**
- 增加操作步骤
- 编辑体验不流畅

### 4. "代理配置"专业性过高
**问题：**
- "NewAPI 令牌"、"HTTP 头部 JSON"对普通用户不友好
- 没有说明这些配置的使用场景
- JSON 编辑器容易出错

**影响：**
- 普通用户困惑："我需要配置这些吗？"
- 高级用户也可能因格式错误而保存失败

## 改进方案

### 方案 A：扁平化 + 分组优化（推荐）

**结构：**
```
┌─────────────────────────────────────┐
│ 添加站点/编辑站点                      │
├─────────────────────────────────────┤
│ 【基础信息】                          │
│ 显示名称: [____________]              │
│ Base URL: [____________]              │
│   [+ 添加线路]                        │
│ API Key:  [____________]              │
│   [+ 添加密钥]                        │
│ 连接协议: [下拉选择] [测试连接]       │
│                                       │
│ ▼ 可选配置                            │
│   写入预览: [下拉选择] [图标预览]     │
│   NewAPI 令牌: [__________]           │
│   代理 HTTP 头部: [展开编辑]          │
│                                       │
│ ▼ Codex 高级能力                      │
│   □ 支持工具调用                      │
│   □ 支持流式响应                      │
│   □ ...                               │
│                                       │
│          [取消]  [测试并保存]          │
└─────────────────────────────────────┘
```

**改动：**
1. 移除"高级配置" Collapse，将"连接协议"提升到基础信息区
2. 合并代理相关配置到"可选配置"
3. 重命名 Collapse 标签：
   - "高级配置" → "可选配置"（降低心理门槛）
   - "Codex 私有能力" → "Codex 高级能力"
4. 移除冗余的 Divider 分隔线
5. "测试连接"按钮移到协议字段旁边

### 方案 B：向导式分步（适合新手）

**结构：**
```
┌─────────────────────────────────────┐
│ 添加站点 [步骤 1/3]                   │
├─────────────────────────────────────┤
│ 【基础信息】                          │
│ 显示名称: [____________]              │
│ Base URL: [____________]              │
│ API Key:  [____________]              │
│                                       │
│          [取消]  [下一步：测试连接]    │
└─────────────────────────────────────┘

┌─────────────────────────────────────┐
│ 添加站点 [步骤 2/3]                   │
├─────────────────────────────────────┤
│ 【连接配置】                          │
│ 连接协议: [自动检测中...]             │
│ ✓ 连接成功！检测到 15 个模型          │
│                                       │
│ □ 使用代理转发                        │
│ □ 配置自定义 HTTP 头部                │
│                                       │
│       [上一步]  [下一步：高级选项]     │
└─────────────────────────────────────┘

┌─────────────────────────────────────┐
│ 添加站点 [步骤 3/3]                   │
├─────────────────────────────────────┤
│ 【可选配置】                          │
│ 写入预览: [使用站点图标]              │
│ Codex 能力: [自动检测] [手动配置]     │
│                                       │
│ ℹ️ 这些配置可以稍后在编辑中修改         │
│                                       │
│       [上一步]  [完成]                 │
└─────────────────────────────────────┘
```

**特点：**
- 将复杂表单拆分为 3 步
- 每步聚焦一个主题
- 自动检测协议和能力，减少手动配置

### 方案 C：智能默认 + 极简表单（最激进）

**结构：**
```
┌─────────────────────────────────────┐
│ 添加站点                              │
├─────────────────────────────────────┤
│ 显示名称: [____________]              │
│ Base URL: [____________]              │
│ API Key:  [____________]              │
│                                       │
│ [测试连接]                            │
│                                       │
│ ⚙️ 需要更多配置？[展开高级选项]        │
│                                       │
│          [取消]  [保存]               │
└─────────────────────────────────────┘
```

**策略：**
- 只显示必填字段
- 协议、能力、代理全部自动检测
- 高级选项收起在一个不显眼的链接里
- 适合 95% 的常规场景

## 具体优化建议

### 优先级 P0（必须改）
1. **提升"连接协议"和"测试连接"** 到基础区域
2. **移除"高级配置"内部的 Divider**，减少视觉噪音
3. **重命名标签**：
   - "高级配置" → "可选配置"
   - "站点信息" → 删除（合并到外层）

### 优先级 P1（建议改）
4. **合并代理配置**，使用 Checkbox 控制展开
5. **NewAPI 令牌添加说明**："仅使用 NewAPI 代理时需要"
6. **HTTP 头部 JSON** 改为键值对编辑器（类似 Postman）

### 优先级 P2（可选）
7. **记住 Collapse 展开状态**（localStorage）
8. **添加"快速模式/完整模式"切换**
9. **编辑时自动展开有值的 Collapse**

## 推荐实施路径

**第一步（快速改善）：** 方案 A - 扁平化
- 工作量：中等（1-2 小时）
- 风险：低
- 收益：立即改善布局和可发现性

**第二步（体验提升）：** 优化细节
- 添加字段说明
- 改进 JSON 编辑器
- 记住展开状态

**第三步（长期目标）：** 方案 B 或 C
- 需要更多用户研究
- 根据用户反馈选择方向
